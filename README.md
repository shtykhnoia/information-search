# Поисковый движок по фильмам и сериалам

Учебный проект курса [«Информационный поиск»](https://github.com/toshunster/MAI-IR). Корпус — статьи о фильмах и сериалах из русской Википедии и Викицитатника.

## Поисковый робот

```bash
docker compose up -d
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python crawler/crawler.py crawler/config.yaml
```

Остановить можно в любой момент через Ctrl+C. Повторный запуск той же командой продолжает с места остановки.

Скачанные документы видны в mongo-express: http://localhost:8081, база `search_engine`, коллекция `documents`.

### Конфиг

| Поле | Назначение |
|---|---|
| `db.uri`, `db.name` | подключение к MongoDB |
| `logic.delay_seconds` | пауза перед каждым HTTP-запросом |
| `logic.recrawl_seconds` | через сколько секунд перепроверять скачанную страницу |
| `logic.user_agent` | User-Agent робота |
| `sources` | источники: название, адрес сайта и категории, статьи которых нужно скачать |

### Как работает

1. Для каждой категории робот получает список статей через MediaWiki API пачками по 500. URL нормализуются, запрещённые в `robots.txt` отбрасываются, остальные попадают в очередь `frontier`. После каждой пачки позиция в категории сохраняется в `categories`.
2. Из очереди берётся страница с наименьшим `next_crawl`. После обработки ей назначается `next_crawl = сейчас + recrawl_seconds`. Пока страница не обработана, она остаётся первой в очереди, поэтому после остановки робот продолжает именно с неё.
3. При повторной обкачке отправляется `If-Modified-Since` со значением `Last-Modified` из прошлого ответа. Если сервер ответил `304 Not Modified`, документ не перезаписывается.
4. После прохода по очереди робот ждёт ближайшую повторную проверку. Раз в `recrawl_seconds` он заново проходит списки категорий, чтобы найти новые статьи.

Подробное объяснение с примерами — в [docs/crawler.md](docs/crawler.md).

На ответ `429 Too Many Requests` робот ждёт столько, сколько указано в `Retry-After` (или минуту), и повторяет запрос. Если сервер ответил на страницу другой ошибкой (404, 5xx), она откладывается до следующей проверки. При обрыве сети робот завершается, перезапуск продолжит с той же страницы.

### Коллекции MongoDB

| Коллекция | Поля |
|---|---|
| `documents` | `url` — нормализованный URL, `html` — исходный HTML, `source` — название источника, `crawled_at` — время скачивания (Unix timestamp) |
| `frontier` | `url`, `source`, `next_crawl` — когда обкачать страницу, `last_modified` — заголовок из последнего ответа |
| `categories` | `_id` — `источник:категория`, `continue` — позиция в списке статей, `done` — категория пройдена, `listed_at` — время последней пачки |

### Тесты

```bash
.venv/bin/python -m unittest discover crawler -v
```

Нужна запущенная MongoDB (по умолчанию `mongodb://127.0.0.1:27017`, другой адрес задаётся переменной `TEST_MONGO_URI`). Тесты поднимают локальный сайт, имитирующий MediaWiki, и работают во временных базах `test_*`.
