# Код робота построчно

Здесь разобран каждый кусок [crawler/crawler.py](../crawler/crawler.py): что делает строка, зачем она нужна и какие значения в ней получаются на реальных данных. Общая идея робота (очередь, проходы, что будет при остановке) описана в [crawler.md](crawler.md). Её полезно прочитать первой.

Номера строк соответствуют текущей версии файла.

## Общая картина

Программа — один класс `Crawler` и функция `main`. Методы вызывают друг друга так:

```text
main()                              читает конфиг, подключается к MongoDB
└── Crawler.run()                   бесконечный цикл проходов
    ├── discover(source)            для каждого сайта
    │   ├── get(".../robots.txt")
    │   └── discover_category(...)  для каждой категории
    │       └── get(".../w/api.php")    список статей пачками по 500
    │           └── normalize_url(...)
    └── crawl_due_pages()           один проход по очереди
        └── next_page_of_each_source()  по странице от каждого сайта
            └── crawl(page)         скачать или перепроверить страницу
                └── get(url)        HTTP-запрос с паузой
```

## Немного Python, который встречается в коде

| Конструкция | Что значит |
|---|---|
| `import x`, `from x import y` | Подключить библиотеку `x` или взять из неё только `y` |
| `def f(a, b):` | Объявить функцию с параметрами `a` и `b` |
| `class Crawler:` | Объявить класс — «чертёж» объекта, который хранит данные и умеет что-то делать |
| `self` | Сам объект внутри своих методов. `self.delay_seconds = 1` — запомнить значение в объекте, чтобы другие методы его видели |
| `{"a": 1}` | Словарь: ключ → значение. `d["a"]` — взять значение по ключу, ошибка, если ключа нет. `d.get("a", 0)` — то же, но вернуть `0`, если ключа нет |
| `[1, 2, 3]` | Список |
| `(1, 2)` | Кортеж — список, который нельзя менять |
| `a, b = (1, 2)` | Распаковка: `a = 1`, `b = 2` |
| `[f(x) for x in xs]` | Списковое включение: применить `f` к каждому `x` и собрать результаты в список |
| `x if условие else y` | Тернарный оператор: `x`, если условие истинно, иначе `y` |
| `while x := f():` | «Моржовый» оператор: вызвать `f()`, положить результат в `x` и продолжать цикл, пока `x` не пустой |
| `f"{a}:{b}"` | f-строка: подставить значения `a` и `b` в текст |
| `**d` | Развернуть словарь `d` в именованные аргументы или в другой словарь |
| `with open(...) as file:` | Открыть ресурс и гарантированно закрыть его, когда блок закончится, даже при ошибке |
| `try: ... except X: ...` | Попробовать выполнить код. Если случилась ошибка типа `X`, выполнить блок `except` вместо падения |
| Пустые `[]`, `{}`, `""`, `0`, `None` | В условиях считаются «ложью». Поэтому `if page:` значит «если страница есть» |

## Конфиг: crawler/config.yaml

```yaml
db:
  uri: mongodb://127.0.0.1:27017
  name: search_engine

logic:
  delay_seconds: 1
  recrawl_seconds: 86400
  user_agent: MAI-IR-crawler/1.0 (https://github.com/shtykhnoia/information-search)

sources:
  - name: wikipedia
    url: https://ru.wikipedia.org
    categories:
      - Категория:Фильмы по алфавиту
      - Категория:Телесериалы по алфавиту
  - name: wikiquote
    ...
```

YAML — формат «ключ: значение», вложенность задаётся отступами, а `-` означает элемент списка. После чтения (строка 147) это становится обычным словарём Python:

```python
{
    "db": {"uri": "mongodb://127.0.0.1:27017", "name": "search_engine"},
    "logic": {"delay_seconds": 1, "recrawl_seconds": 86400, "user_agent": "MAI-IR-crawler/1.0 (...)"},
    "sources": [
        {"name": "wikipedia", "url": "https://ru.wikipedia.org", "categories": ["Категория:Фильмы по алфавиту", ...]},
        {"name": "wikiquote", ...},
    ],
}
```

- `db.uri` — адрес MongoDB. `127.0.0.1` — этот же компьютер, `27017` — стандартный порт MongoDB.
- `db.name` — имя базы внутри MongoDB.
- `logic.delay_seconds` — сколько секунд ждать между запросами к одному сайту.
- `logic.recrawl_seconds` — через сколько секунд перепроверять скачанную страницу. `86400` — это сутки.
- `logic.user_agent` — как робот представляется сайтам в заголовке `User-Agent`.
- `sources` — список сайтов. `name` попадёт в поле `source` каждого документа, `url` — адрес сайта, `categories` — какие категории статей обойти.

## Нормализация адреса (строки 18–20)

```python
def normalize_url(url):
    scheme, host, path, query, _ = urlsplit(url)
    return urlunsplit((scheme.lower(), host.lower(), quote(unquote(path)), query, ""))
```

Задача функции — чтобы одна и та же страница всегда имела один и тот же адрес, как бы его ни записали.

**Строка 19.** `urlsplit` разбирает адрес на пять частей. Например:

```python
urlsplit("https://RU.Wikipedia.org/wiki/Матрица_(фильм)#Сюжет")
# scheme='https', netloc='RU.Wikipedia.org', path='/wiki/Матрица_(фильм)', query='', fragment='Сюжет'
```

Распаковка кладёт части в переменные `scheme`, `host`, `path`, `query`, а пятую часть (фрагмент после `#`) — в `_`. Подчёркивание по соглашению значит «это значение не нужно».

**Строка 20.** Собирает адрес обратно, по пути приводя части к единому виду:

- `scheme.lower()`, `host.lower()` — схема и домен в нижнем регистре: `RU.Wikipedia.org` → `ru.wikipedia.org`. Регистр в домене не важен, поэтому так можно.
- `quote(unquote(path))` — сначала раскодировать путь (`%D0%9C` → `М`), потом закодировать заново. В итоге путь всегда записан одинаково, как бы он ни был записан на входе: кириллица, скобки — всё в `%XX`:
  ```text
  /wiki/Матрица_(фильм)          → /wiki/%D0%9C%D0%B0%D1%82%D1%80%D0%B8%D1%86%D0%B0_%28%D1%84%D0%B8%D0%BB%D1%8C%D0%BC%29
  /wiki/%D0%9C...%D0%B0_(...)    → то же самое
  ```
- `query` — параметры после `?` оставляются как есть.
- `""` вместо фрагмента — `#Сюжет` отбрасывается: это место на той же странице, а не другая страница.

## Класс Crawler: конструктор (строки 23–41)

`__init__` — специальный метод. Python вызывает его сам, когда создаётся объект: `Crawler(config, db)` в строке 152.

```python
class Crawler:
    def __init__(self, config, db):
        logic = config["logic"]
        self.delay_seconds = logic["delay_seconds"]
        self.recrawl_seconds = logic["recrawl_seconds"]
        self.user_agent = logic["user_agent"]
        self.sources = config["sources"]
```

- **Строка 24.** Конструктор получает конфиг (словарь из YAML) и `db` — уже подключённую базу MongoDB.
- **Строка 25.** `logic` — короткое имя для `config["logic"]`, чтобы не писать длинно три раза.
- **Строки 26–29.** Достаём настройки и запоминаем их в объекте (`self.`), чтобы ими пользовались другие методы. Если в конфиге нет какого-то ключа, здесь будет ошибка `KeyError` с его именем: сразу понятно, что исправить.

```python
        self.http = requests.Session()
        self.http.headers["User-Agent"] = self.user_agent
        self.last_response_at = {}
```

- **Строка 31.** `Session` — «сеанс» HTTP. В отличие от отдельных вызовов `requests.get`, он держит соединение с сайтом открытым между запросами. Это быстрее: не нужно каждый раз заново устанавливать защищённое соединение.
- **Строка 32.** Каждый запрос этого сеанса будет отправлять заголовок `User-Agent` из конфига. Так сайт видит, кто к нему ходит.
- **Строка 33.** Пустой словарь «хост → момент, когда закончился последний запрос к нему». Нужен для пауз: `{"ru.wikipedia.org": 5123.4, "ru.wikiquote.org": 5124.1}`.

```python
        self.documents = db.documents
        self.frontier = db.frontier
        self.categories = db.categories
```

- **Строки 35–37.** Три коллекции MongoDB (коллекция — аналог таблицы). Если коллекции нет, MongoDB создаст её сама при первой записи.
  - `documents` — скачанные статьи,
  - `frontier` — очередь «что качать и когда»,
  - `categories` — закладки в списках категорий.

```python
        self.documents.create_index("url", unique=True)
        self.frontier.create_index("url", unique=True)
        self.frontier.create_index([("next_crawl", 1), ("_id", 1)])
        self.frontier.create_index([("source", 1), ("next_crawl", 1), ("_id", 1)])
```

Индекс — как алфавитный указатель в книге: по нему MongoDB находит нужные записи, не просматривая всю коллекцию. `create_index` ничего не делает, если такой индекс уже есть, поэтому вызывать его при каждом запуске безопасно.

- **Строки 38–39.** `unique=True` — уникальный индекс по `url`. MongoDB не даст записать два документа с одинаковым адресом. Это главная защита от дубликатов.
- **Строка 40.** Индекс для поиска «страницы с самым ранним `next_crawl`» (строка 48). `1` значит «по возрастанию».
- **Строка 41.** Индекс для поиска «самая ранняя страница конкретного источника» (строка 61).

## run — главный цикл (строки 43–51)

```python
    def run(self):
        while True:
            for source in self.sources:
                self.discover(source)
            self.crawl_due_pages()
            next_page = self.frontier.find_one(sort=[("next_crawl", 1)])
            next_check = next_page["next_crawl"] if next_page else time.time() + self.recrawl_seconds
            log.info("проход завершён, следующая проверка: %s", time.ctime(next_check))
            time.sleep(max(0, next_check - time.time()))
```

- **Строка 44.** `while True` — бесконечный цикл. Робот работает, пока его не остановят через Ctrl+C. Один оборот цикла — один «проход».
- **Строки 45–46.** Для каждого сайта из конфига дополнить очередь новыми статьями из категорий (см. `discover`).
- **Строка 47.** Скачать или перепроверить все страницы, которым пора (см. `crawl_due_pages`).
- **Строка 48.** Найти в очереди страницу с самым маленьким `next_crawl`, то есть ту, которую нужно проверить раньше всех. `find_one` возвращает одну запись (словарь) или `None`, если очередь пуста.
- **Строка 49.** Когда начинать следующий проход: в `next_crawl` этой страницы. Если очередь пуста (`next_page` равно `None`), просто через `recrawl_seconds`. `time.time()` — текущее время в секундах с 1 января 1970 года (Unix timestamp), например `1792609922.86`.
- **Строка 50.** Написать в лог, когда будет следующая проверка. `time.ctime` превращает число в читаемую дату: `Thu Oct 22 22:40:48 2026`. `%s` в строке заменяется вторым аргументом.
- **Строка 51.** Уснуть до этого момента. `max(0, ...)` нужен, потому что момент мог уже пройти: тогда разность отрицательная, а `time.sleep` с отрицательным числом падает с ошибкой. В этом случае спим 0 секунд и сразу начинаем новый проход.

## crawl_due_pages — один проход (строки 53–57)

```python
    def crawl_due_pages(self):
        pass_started = time.time()
        while pages := self.next_page_of_each_source(pass_started):
            for page in pages:
                self.crawl(page)
```

- **Строка 54.** Запомнить время начала прохода.
- **Строка 55.** Взять по одной «просроченной» странице от каждого сайта (не позже `pass_started`). Пока список не пуст, продолжать. Когда у всех сайтов такие страницы кончились, функция вернёт `[]`, и цикл закончится.
- **Строки 56–57.** Обработать полученные страницы по очереди: страницу Википедии, страницу Викицитатника, и снова.

Почему именно `pass_started`, а не «сейчас». Каждая обработанная страница получает `next_crawl` в будущем (строка 108) и в этот проход больше не попадает, поэтому список «кому пора» только уменьшается и проход обязательно заканчивается. Если бы условие было «срок наступил к текущему моменту», то при обходе дольше суток подходил бы срок уже обработанных страниц, и проход никогда бы не закончился.

## next_page_of_each_source (строки 59–64)

```python
    def next_page_of_each_source(self, due_by):
        pages = [
            self.frontier.find_one({"source": source["name"], "next_crawl": {"$lte": due_by}}, sort=[("next_crawl", 1), ("_id", 1)])
            for source in self.sources
        ]
        return [page for page in pages if page]
```

- **Строки 60–63.** Для каждого сайта найти в очереди одну запись:
  - `{"source": "wikipedia", "next_crawl": {"$lte": due_by}}` — фильтр: «этот источник и `next_crawl` ≤ `due_by`». `$lte` — оператор MongoDB «меньше или равно» (less than or equal);
  - `sort=[("next_crawl", 1), ("_id", 1)]` — из подходящих взять ту, у которой `next_crawl` меньше всех, а при равенстве — с меньшим `_id`. `_id` MongoDB создаёт сама, и он растёт примерно в порядке добавления записей. Поэтому новые страницы (у всех `next_crawl = 0`) берутся в том порядке, в котором попали в очередь.

  Получается список из двух элементов, например `[{...страница Википедии...}, None]`. `None` — если у Викицитатника страниц на этот проход не осталось.
- **Строка 64.** Убрать из списка `None`: `[page for page in pages if page]` оставляет только найденные страницы.

## discover — подготовка сайта (строки 66–70)

```python
    def discover(self, source):
        robots = RobotFileParser()
        robots.parse(self.get(source["url"] + "/robots.txt").text.splitlines())
        for category in source["categories"]:
            self.discover_category(source, category, robots)
```

- **Строка 67.** Создать пустой разборщик `robots.txt`.
- **Строка 68.** Скачать `https://ru.wikipedia.org/robots.txt`, взять текст ответа (`.text`), разбить на строки (`.splitlines()`) и отдать разборщику. Теперь он знает, какие адреса сайт запрещает роботам.
- **Строки 69–70.** Для каждой категории из конфига дособрать список статей. Разборщик `robots` передаётся дальше, чтобы проверять каждый адрес.

## discover_category — список статей категории (строки 72–103)

Это самый длинный метод. Он спрашивает у Википедии статьи категории пачками по 500 и после каждой пачки сохраняет закладку.

```python
    def discover_category(self, source, category, robots):
        state_id = f"{source['name']}:{category}"
        state = self.categories.find_one({"_id": state_id})
        if state is None or (state["done"] and state["listed_at"] + self.recrawl_seconds <= time.time()):
            state = {"_id": state_id, "continue": {}, "done": False}
```

- **Строка 73.** Имя записи о категории, например `"wikipedia:Категория:Фильмы по алфавиту"`. У каждой пары «сайт + категория» своя закладка.
- **Строка 74.** Найти закладку в коллекции `categories`. Если её нет, `find_one` вернёт `None`.
- **Строка 75.** Нужно ли начинать перечисление с начала? Да, если:
  - закладки ещё нет (первый запуск), **или**
  - категория уже пройдена до конца (`done`) **и** с последней пачки (`listed_at`) прошло не меньше `recrawl_seconds`. Пора пройти её заново, чтобы найти новые статьи.
- **Строка 76.** Тогда закладка «с нуля»: `continue` пустой (с начала списка), `done` ложь.

  В остальных случаях используется закладка из базы. Если робота остановили посреди категории, в ней `done: False` и сохранённый `continue`, и перечисление продолжится с того же места. Если категория пройдена недавно, в ней `done: True`, и цикл ниже не выполнится ни разу.

```python
        while not state["done"]:
            response = self.get(source["url"] + "/w/api.php", params={
                "action": "query",
                "format": "json",
                "formatversion": 2,
                "generator": "categorymembers",
                "gcmtitle": category,
                "gcmnamespace": 0,
                "gcmlimit": "max",
                "prop": "info",
                "inprop": "url",
                **state["continue"],
            }).json()
```

- **Строка 77.** Повторять, пока категория не пройдена.
- **Строки 78–89.** Запрос к API MediaWiki — специальному адресу `/w/api.php`, который отвечает данными в JSON, а не HTML-страницей. `params` — параметры, `requests` сам допишет их к адресу после `?`. Что значит каждый:
  - `action=query` — «запрос данных»;
  - `format=json`, `formatversion=2` — ответ в JSON, в новом, более простом формате;
  - `generator=categorymembers`, `gcmtitle=<категория>` — «возьми страницы из этой категории»;
  - `gcmnamespace=0` — только обычные статьи, без подкатегорий, шаблонов и служебных страниц;
  - `gcmlimit=max` — сколько можно за раз, для обычных пользователей это 500;

## crawl — скачать или перепроверить страницу (строки 105–124)

На вход приходит запись из очереди, например:

```python
{"_id": ObjectId("..."), "url": "https://ru.wikipedia.org/wiki/...", "source": "wikipedia",
 "next_crawl": 1792609922, "last_modified": "Wed, 07 Oct 2026 10:55:45 GMT"}
```

У новой страницы `last_modified` нет.

```python
    def crawl(self, page):
        url = page["url"]
        headers = {"If-Modified-Since": page["last_modified"]} if page.get("last_modified") else {}
        update = {"next_crawl": int(time.time()) + self.recrawl_seconds}
```

- **Строка 106.** Короткое имя для адреса.
- **Строка 107.** Заголовки запроса. Если страницу уже скачивали и сайт тогда сообщил дату изменения, отправить её в заголовке `If-Modified-Since`: «отдай страницу, только если она менялась после этой даты». Для новой страницы заголовков нет (`{}`).
- **Строка 108.** Что записать в очередь после обработки: следующая проверка через `recrawl_seconds` от текущего момента. Например, сейчас `1792609922`, значит `next_crawl = 1792696322` — ровно через сутки.

```python

            if response.status_code == 304:
                log.info("не изменилась %s", unquote(url))
            else:
                self.documents.replace_one({"url": url}, {
                    "url": url,
                    "html": response.text,
                    "source": page["source"],
                    "crawled_at": int(time.time()),
                }, upsert=True)
                update["last_modified"] = response.headers.get("Last-Modified")
                log.info("скачана %s", unquote(url))
```

- **Строка 110.** Запросить страницу (см. `get`).
- **Строки 111–112.** Код ответа `304 Not Modified` — сайт говорит «не менялась», тела ответа нет. В базу ничего не пишем, только сообщаем в лог. `unquote(url)` превращает `%D0%9C...` обратно в кириллицу, чтобы лог можно было прочитать.
- **Строки 113–119.** Иначе пришла страница (`200 OK`). Записать документ в `documents`. `replace_one` с `upsert=True` заменит старую версию с этим `url` или создаст новую запись. Поля документа:
  - `url` — нормализованный адрес;
  - `html` — текст ответа как есть. `response.text` декодирует байты в строку по кодировке из заголовка `Content-Type`;
  - `source` — название источника из очереди;
  - `crawled_at` — время скачивания, целое число секунд (Unix timestamp).
- **Строка 120.** Запомнить для очереди новую дату изменения из заголовка ответа `Last-Modified`. Если сайт её не прислал, будет `None`, и в следующий раз страница скачается целиком (строка 107 не добавит заголовок).
- **Строка 121.** Сообщение в лог.

```python
        except (requests.HTTPError, DocumentTooLarge) as error:
            log.warning("ошибка %s: %s", unquote(url), error)
        self.frontier.update_one({"_id": page["_id"]}, {"$set": update})
```

- **Строки 122–123.** Если сайт ответил ошибкой (`HTTPError`: 404, 500 и т. п.) или страница не влезла в MongoDB (`DocumentTooLarge`), не падать, а написать предупреждение. Ошибки сети (нет интернета, тайм-аут) здесь не ловятся: робот завершится, а после перезапуска продолжит с этой же страницы.
- **Строка 124.** Записать в очередь `next_crawl` (и `last_modified`, если он есть в `update`). `$set` меняет только указанные поля, остальные остаются. Эта строка выполняется в любом случае — после скачивания, после `304` и после ошибки. Поэтому каждая обработанная страница уходит в конец очереди, и ошибочная страница не блокирует остальные.

  Порядок важен. Документ сохраняется (строка 114) **до** обновления очереди (строка 124). Если робот упадёт между ними, страница останется «просроченной» и скачается ещё раз. Дубликата не будет: `url` уникален, `replace_one` просто перезапишет документ.

## get — HTTP-запрос с паузой (строки 126–139)

Все запросы к сайтам — и `robots.txt`, и API, и страницы — проходят через этот метод.

```python
    def get(self, url, **kwargs):
        host = urlsplit(url).netloc
        while True:
            time.sleep(max(0, self.last_response_at.get(host, 0) + self.delay_seconds - time.monotonic()))
            response = self.http.get(url, timeout=REQUEST_TIMEOUT_SECONDS, **kwargs)
            self.last_response_at[host] = time.monotonic()
            if response.status_code != 429:
                break
```

- **Строка 126.** `**kwargs` собирает все дополнительные именованные аргументы (`params=...`, `headers=...`) в словарь и передаёт их дальше, в `requests` (строка 130).
- **Строка 127.** Хост — домен из адреса: из `https://ru.wikipedia.org/w/api.php?...` получается `ru.wikipedia.org`. Пауза считается для каждого хоста отдельно.
- **Строка 128.** Цикл нужен для повтора после ответа `429`.
- **Строка 129.** Подождать, пока с конца прошлого запроса к этому хосту не пройдёт `delay_seconds`. Пример: прошлый запрос к Википедии закончился в момент `100.0`, пауза `1`, сейчас `100.3`. Ждём `100.0 + 1 − 100.3 = 0.7` секунды. Если к хосту ещё не ходили, `.get(host, 0)` даёт 0, разность отрицательная, и `max(0, ...)` превращает её в 0: ждать не нужно.

  `time.monotonic()` — «секундомер», который только растёт. В отличие от `time.time()`, его не сбивает перевод часов на компьютере, поэтому для измерения пауз он надёжнее.

  Пока робот ждёт паузу Википедии, он не простаивает: `crawl_due_pages` по очереди даёт ему страницы Викицитатника, а у того своя пауза, которая к этому времени уже прошла.
- **Строка 130.** Сам запрос. `timeout` — не ждать ответа дольше 30 секунд.
- **Строка 131.** Запомнить, когда закончился запрос к этому хосту.
- **Строки 132–133.** Если ответ не `429`, выйти из цикла.

```python
            retry_after = response.headers.get("Retry-After", "")
            wait_seconds = int(retry_after) if retry_after.isdigit() else DEFAULT_RETRY_AFTER_SECONDS
            log.warning("сервер просит подождать %d с", wait_seconds)
            time.sleep(wait_seconds)
        response.raise_for_status()
        return response
```

- **Строки 134–137.** Код `429 Too Many Requests` — сайт просит ходить реже. Сколько ждать, он обычно пишет в заголовке `Retry-After` числом секунд, например `"120"`. `isdigit()` проверяет, что там действительно число. `Retry-After` может прийти и в виде даты, и тогда ждём минуту по умолчанию. После сна цикл повторяет тот же запрос.
- **Строка 138.** `raise_for_status()` выбрасывает `requests.HTTPError`, если код ответа 400 и больше (ошибка клиента или сервера). Для `200` и `304` ничего не происходит. Ошибку ловит `crawl` (строка 122).
- **Строка 139.** Вернуть ответ.

## Путь одной статьи от категории до базы

1. `run` → `discover(wikipedia)` скачивает `robots.txt` Википедии.
2. `discover_category` запрашивает у API пачку статей «Фильмов по алфавиту». В пачке есть `https://ru.wikipedia.org/wiki/Интерстеллар`.
3. `normalize_url` превращает адрес в `https://ru.wikipedia.org/wiki/%D0%98%D0%BD%D1%82...`. `robots.txt` разрешает его, и в `frontier` появляется запись с `next_crawl: 0`. Закладка категории сохраняется.
4. Списки всех категорий дособраны, `run` вызывает `crawl_due_pages`.
5. `next_page_of_each_source` доходит до «Интерстеллара»: `next_crawl = 0`, это раньше начала прохода.
6. `crawl` вызывает `get`, тот выжидает паузу для `ru.wikipedia.org` и делает запрос. Заголовка `If-Modified-Since` нет: страницу ещё не качали.
7. Ответ `200`. В `documents` записывается `{url, html, source: "wikipedia", crawled_at}`. В `frontier` — `next_crawl` через сутки и `last_modified` из ответа.
8. Через сутки страница снова оказывается «просроченной». `crawl` отправляет `If-Modified-Since`. Если статья не менялась, ответ `304`, документ не трогается, `next_crawl` сдвигается ещё на сутки. Если менялась — ответ `200`, документ перезаписывается.

## Скрипт статистики: corpus/stats.py

Это отдельная небольшая программа для лабораторной №1. Она не скачивает ничего нового, а только читает документы, которые уже скачал робот.

```python
SAMPLE_SIZE = 20
NOISE = "script, style, table, figure, sup.reference, .mw-editsection, .reflist, .references, .navbox, .hatnote, .noprint"
```

- `SAMPLE_SIZE` — сколько документов каждого источника брать в выборку.
- `NOISE` — CSS-селекторы элементов, которые не являются текстом статьи. Запятая значит «или». `script`, `style`, `table`, `figure` — теги; `.reflist` — элементы с классом `reflist`; `sup.reference` — тег `sup` с классом `reference` (сноска `[1]`).

```python
def extract_text(html):
    content = BeautifulSoup(html, "html.parser").select_one("#mw-content-text .mw-parser-output")
    for element in content.select(NOISE):
        element.decompose()
    return " ".join(content.get_text(" ").split())
```

- `BeautifulSoup(html, "html.parser")` разбирает HTML в дерево элементов.
- `.select_one("#mw-content-text .mw-parser-output")` находит блок со статьёй: элемент класса `mw-parser-output` внутри элемента с `id="mw-content-text"`. Шапка, меню и подвал сайта остаются снаружи.
- `content.select(NOISE)` находит внутри статьи все «шумовые» элементы, а `decompose()` удаляет каждый вместе с содержимым.
- `content.get_text(" ")` берёт весь оставшийся текст, соединяя куски через пробел.
- `.split()` режет текст по любым пробельным символам (пробелы, переводы строк, табуляции), а `" ".join(...)` склеивает обратно через один пробел. Так лишние пробелы и пустые строки схлопываются.

```python
def kilobytes(size):
    return f"{size / 1024:.1f} КБ"
```
